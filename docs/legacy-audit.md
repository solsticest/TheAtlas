# Legacy audit — TheAtlas v4.1

Дата аудита: 2026-11-06  
Исходная ветка: `main` @ `8f64d263fc6676deb2cc75fa08116a2b6cc34997`  
Рабочая ветка миграции: `feat/react-atlas-migration`

## Цель

Перенести существующий TheAtlas на React + TypeScript + Vite + Node.js/Express + Prisma/SQLite без потери пользовательских данных и без незаметного изменения поведения существующего атласа.

Chronicle/исторические таймлайны не входят в P0 этой миграции. Новый Atlas должен оставить чистый интеграционный шов для Chronicle, но сначала нужно добиться паритета с v4.1.

## Что реально есть в репозитории

- `index.html`, `css/style.css`, `css/v4.css`.
- `js/app.js` — основная Leaflet-логика, модель данных, геометрия вложенных карт, редактор.
- `js/atlas-v4.js` — поиск, каталог, статьи, линейка, совмещение по двум точкам, сохранение и backup.
- `js/atlas-math.js` — чистая геометрия `routeLength` и `alignTwoPoints`.
- `js/main-folder.js` — File System Access API + IndexedDB для основной папки.
- `data/atlas.json` schema version 4.
- `maps/` — 5 файлов: 2 demo SVG и 3 реальные карты.
- `tests/regression.cjs`, `tests/main-folder.cjs`, `tests/html-tree.py`.
- `media/` сейчас отсутствует в Git, но v4.1 поддерживает её и ссылки на media входят в формат статей.

## Контракты, которые нельзя потерять

### 1. Координатная модель

Leaflet работает с `L.CRS.Simple`. Координаты направлены вверх, начало — снизу слева.

`MapLayer.bounds` хранятся НЕ в глобальных координатах мира, а в пиксельной системе координат родительского изображения. `worldBox()` рекурсивно преобразует их в глобальные координаты.

Следствие: нельзя просто положить `bounds` в БД и трактовать их как world-space.

### 2. Вложенность карт

`parentId` образует дерево внутри мира. Legacy `normalize()`:
- сохраняет существующие ID;
- исправляет дубли/отсутствующие ID;
- разрывает битые parent-ссылки и циклы;
- не уничтожает при этом данные изображения.

Импортёр должен валидировать эти случаи в dry-run, а не тихо менять исходный JSON.

### 3. Поворот

`rotation` хранится в градусах 0..359 и применяется визуально к bitmap внутри Leaflet overlay.

Важное legacy-ограничение: дочерние карты и маркеры не наследуют визуальный поворот родителя. Нельзя «исправить» это при миграции — это изменит расположение существующих данных.

### 4. Zoom semantics

- Карта-слой: `showAtZoom` + `fadeRange`.
- Локация: `minZoom` — дискретный порог.
- Zoom дробный (`zoomSnap: 0`).

Новый renderer должен сохранить эти различия.

### 5. Неизвестные поля

Legacy `normalize()` изменяет известные поля, но сохраняет неизвестные поля объектов. Это важный контракт forward/backward compatibility.

В новой БД неизвестные legacy-поля нельзя бесследно отбросить. Для импортируемых сущностей нужен `legacyExtra`/JSON metadata либо эквивалентный механизм.

### 6. Статьи

`Location.description` и `Location.article` — независимые поля.

`article` — санитизированный HTML. Разрешены внутренние ссылки через:
- `data-world`
- `data-location`
- `href="#location"`

Локальные изображения статей представлены через `img[data-asset="<filename>"]` и живут в `media/`.

Импорт обязан сохранить HTML-семантику и ссылки, но повторно санитизировать содержимое на доверенной серверной стороне.

### 7. Сохранение и backup

Legacy write contract:
1. Синхронизировать текущую статью/drag.
2. Снять immutable snapshot состояния.
3. Проверить, что `atlas.json` не изменён извне.
4. Проверить наличие всех требуемых `maps/` и `media/` assets.
5. Записать точную предыдущую версию JSON в `data/backups/`.
6. Записать staged assets.
7. Ещё раз проверить concurrent external write.
8. Только после этого заменить `data/atlas.json`.

При ошибке пользовательские данные на диске должны оставаться нетронутыми.

В новой серверной архитектуре File System Access API уйдёт, но семантика атомарности, резервирования и проверки ссылочной целостности должна сохраниться.

### 8. Undo/camera

Legacy undo:
- хранит до 60 snapshot-ов;
- коалесцирует slider/article edits;
- восстанавливает данные и staged files;
- не сбрасывает центр камеры и дробный zoom.

При переносе редактора это поведение либо сохраняется, либо явно объявляется backlog; тихо удалить его нельзя.

### 9. Поиск

Поиск глобальный по всем мирам и включает:
- названия миров;
- названия карт;
- имена локаций;
- краткое описание;
- текст HTML-статьи;
- теги.

Переход к результату из другого мира переключает мир и фокусирует карту.

### 10. Просмотр и редактор

Legacy `view mode` — только UI-режим, не авторизация. Новый stack должен разделить:
- публичный read-only UI;
- реальную серверную admin-authorisation.

## Что мигрируется в БД

- `World`

Не переносить Chronicle-модели в P0 Atlas migration.

- `index.html`
- `css/`
- `js/`
- `data/atlas.json`
- `maps/`
- `tests/`

Legacy остаётся эталоном поведения и rollback-вариантом.

## Регрессионный baseline

Существующие тесты уже фиксируют, среди прочего:

- загрузку реального v3/v4 проекта без потери вложенности;
- сохранение неизвестных полей;
- undo + fractional zoom;
- поиск по статьям и тегам;
- sanitizer;
- независимость description/article;
- линейку и kmPerPixel;
- view mode;
- two-point alignment;
- round-trip nested coordinate conversion;
- rotated overlays;
- backup-before-write;
- media-before-JSON;
- external-write protection;
- missing-assets protection;
- сохранение пользовательского `data/atlas.json` неизменным во время тестов.

Эти тесты должны продолжать запускаться на протяжении всей миграции.

## Главные риски

1. Потерять parent-relative semantics `bounds`.
2. Ошибочно «унаследовать» rotation детьми.
3. Потерять неизвестные поля JSON при нормализации/Prisma import.
4. Изменить ID или имена asset-файлов.
5. Потерять article HTML / tags / internal links / media references.
6. Перенести CRUD раньше, чем появится безопасный backup/export/restore.
7. Заменить legacy renderer до появления parity-тестов.
8. Смешать миграцию Atlas с Chronicle и резко увеличить объём P0.

## Критерий завершения миграции

Миграция считается успешной только если:
- dry-run и настоящий import дают одинаковые counts/IDs/relations;
- round-trip export не теряет ни одного известного или неизвестного legacy-поля;
- все 3 реальные карты открываются;
- Линвейл → Грейфорд сохраняется;
- Эстара сохраняет координаты, описание, статью и теги;
- zoom/rotation/nested placement совпадают с legacy;
- публичный пользователь не может писать данные;
- admin CRUD переживает рестарт;
- backup + restore проверены;
- legacy regression suite остаётся зелёным.
