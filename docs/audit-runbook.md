# Этап 2 — безопасная проверка данных Atlas v4 (Windows)

Проверка доступна в ветке `feat/react-atlas-migration`.

## Что делает

`scripts/audit-legacy.cjs` только **читает** исходные `data/atlas.json`, `maps/` и, если на них есть ссылки, `media/`.

Проверяет:
- количество миров, слоёв, маркеров, типов, статей;
- ID, отношения parentId и отсутствие циклов;
- типы, координаты и числовые геометрические поля;
- неизвестные поля в исходном JSON;
- наличие и путь каждого файла изображения;
- SHA-256 и размер каждого файла;
- реальные размеры PNG/WebP/SVG, когда их можно определить без декодирования;
- ссылки внутри статей и изображения `data-asset`.

**Не делает:** импорт в SQLite, изменение исходного JSON, удаление или перемещение изображений. Параметр `--apply` намеренно запрещён.

## Как запустить (PowerShell, диск D:)

Если `npm.cmd run dev` уже работает, оставь его окно открытым и запусти отдельный терминал.

```powershell
cd D:\Projects\TheAtlas
git switch feat/react-atlas-migration
git pull --ff-only
npm.cmd run audit:legacy
```

При успехе в конце будет `Итог: ПРОВЕРКА ПРОЙДЕНА; файлы не изменялись.`.

Полный отчёт без изменений исходных файлов можно сохранить вне репозитория:

```powershell
node scripts/audit-legacy.cjs --json > D:\Projects\TheAtlas-audit.json
```

Если в твоём локальном Atlas есть **другие, ещё не отправленные в GitHub карты или статьи**, проверяй их отдельно, указав пути к существующему проекту:

```powershell
node scripts/audit-legacy.cjs --input "D:\MyAtlas\data\atlas.json" --assets-dir "D:\MyAtlas\maps" --media-dir "D:\MyAtlas\media"
```

Замени `D:\MyAtlas` на реальный путь. Если `media/` не существует и на неё нет ссылок, это не ошибка.

## Проверка самого анализатора

```powershell
npm.cmd run test:migration
```

Тесты используют временные файлы вне исходного атласа и очищают их после проверки.

## Что делать, если обнаружены ошибки

Не применяй миграцию и не редактируй JSON вручную. Сохрани результат отчёта, отправь его разработчику. Некоторые несоответствия могут оказаться ошибками исходной версии, а не результатом миграции.

## Перед настоящим импортом в SQLite

Создай полную копию оригинального Atlas **вне репозитория и вне папки, куда пишет импортёр**: `data/atlas.json`, `maps/`, `media/`, `data/backups/`. Затем сравни SHA-256 с отчётом.

Настоящий импорт, Prisma-модели, резервирование базы и round-trip экспорт относятся к следующему этапу, а не к read-only проверке.
